# BusMap 线路标签重叠避免 — 设计文档

## 背景

当查看公交线路图缩放到一定级别时（`minZoomForLabel = 13`），每条线路会显示一个蓝色的折线
和一个白底橙字的名字标签。很多公交线路在同一段路上并线（例如多条线路经过相同的路口或
主干道），这些线路的标签如果都放在各自的路线中点，就会**完全重叠**在一起，用户无法区分。

## 目标

- 在尽可能多的场景下让标签**互不重叠**，用户能同时看清多条线路的名字。
- 当路线完全重合没有空地时，至少让标签**垂直错开**，用户能看出这里有两条线。
- 不增加新的外部依赖。

## 核心方案：像素空间贪心放置

所有逻辑集中在 `RouteLabelManager.updateAll()` 方法中。

### 步骤

#### 1. 可见性过滤

每条线路的 `BMap.Polyline.getBounds()` 返回其地理包围盒。与视口 `map.getBounds()`
做 `intersects()` 判断。完全不进入视口的线路直接隐藏标签，不做后续计算。

#### 2. 候选位置采样

对于可见线路，剔除视口外的坐标点，得到该线路在屏幕中可见的点序列。从这些可见点中**均匀**
取最多 7 个位置作为标签**候选锚点**。采样稀疏化：如果可见点很多（>40），用步长 `floor(n/40)`
粗略扫描降低开销；如果可见点很少（<8），则直接全量使用。

每个候选点通过 `map.pointToOverlayPixel()` 转为屏幕像素坐标 `(x, y)`。

#### 3. AABB 碰撞检测

标签的像素包围盒用以下方式估算：

- 宽度 = 线路名字符数 × `charWidth` + 24px（内边距）
- 高度 = 当前字号 + 10px（上下内边距）
- `charWidth = clampedSize × 0.6`（中文字符约 1 个 em，数字/英文约 0.6em；保守取 0.6）
- 字号随 zoom 级缩放：`baseSize + (zoom - minZoomForLabel) × 0.8`，限制在 10–22px

包围盒左上角为 `(cand.x - 6, cand.y + offsetY - height/2)`，
右下角为 `(cand.x + labelWidth, cand.y + offsetY + height/2)`。

函数维护一个 `occupied` 数组，存放已放置标签的 AABB。新候选与所有已放置标签做
**AABB 相交判断**（`l < occ.r && r > occ.l && t < occ.b && b > occ.t`）。

#### 4. 贪心分配

按线路添加顺序遍历。每条线路依次尝试：7 个候选位置 × 5 档垂直偏移（0, -24, +24, -48, +48
像素） = 最多 35 种组合。选取标准按优先级排列：

1. **重叠数最少**（首要条件）
2. 重叠数相同时，**偏移量绝对值最小**
3. 偏移量也相同时，**距离路线中心最近**（`曼哈顿距离`）

已放置到最优位置的标签立即加入 `occupied` 列表，影响后续线路的选择。

#### 5. 后退策略

如果 35 种组合都有至少 1 个重叠，算法仍然取重叠最少的那个——这意味着即使没有完全空闲
的位置，两条完全重合的路线也会各自偏移到 ±24px 或 ±48px，在视觉上垂直错开。

### 为什么不做地理坐标碰撞？

Baidu Maps JS API 在渲染后不暴露 Label 的像素包围盒，所以无法从 DOM 获取真实尺寸。
本文档的方案通过**先验估计**做碰撞检测，不依赖渲染 Pipeline。

## 调参说明

| 参数 | 值 | 说明 |
|------|-----|------|
| `minZoomForLabel` | 13 | 小于此 zoom 时隐藏所有标签 |
| `候选数` | 7 | 每条线路的候选锚点上限 |
| `垂直偏移` | [0, -24, 24, -48, 48] | 像素偏移，正值为向下 |
| `charWidth` | fontSize × 0.6 | 估计字符宽度 |
| `padding` | 24px (宽) / 10px (高) | 标签内边距 |

如果未来效果需要调整，可以直接修改这些值。
